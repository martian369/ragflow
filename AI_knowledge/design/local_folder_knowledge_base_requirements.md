# 本地文件夹知识库模块需求文档

## 1. 概述

### 1.1 项目背景
当前RAGFlow系统在处理本地文件夹知识库时存在以下问题：
1. 文件上传方式冗余，需要手动逐个上传文件
2. 缺乏自动化的文件扫描和处理机制
3. 无法有效识别和处理重复文件，造成存储浪费
4. 不支持增量更新，每次都需要全量处理文件夹

### 1.2 目标
开发一个本地文件夹知识库模块，实现自动化文件处理、减少存储冗余、支持增量向量化等功能。重点在于：
1. 通过文件内容MD5哈希值识别文件唯一性，避免重复向量化
2. 提供结构化的文件管理界面，支持按文件夹查看状态
3. 最大化复用现有流程、代码和环境
4. 直接使用本地文件进行处理，避免将文件上传到MinIO等存储系统，减少冗余存储

## 2. 功能需求

### 2.1 核心功能

#### 2.1.1 本地文件夹选择与扫描
- [ ] 提供图形界面让用户选择本地文件夹
- [ ] 支持递归扫描文件夹中的所有文件
- [ ] 可配置支持的文件类型后缀（如：.txt, .pdf, .md, .docx等）
- [ ] 自动识别文件的元数据（文件名、大小、修改时间等）

#### 2.1.2 文件去重机制
- [ ] 基于文件内容MD5哈希值进行重复检测（核心去重机制）
- [ ] 基于文件路径和修改时间进行变化检测（辅助检测机制）
- [ ] 避免对相同内容文件的重复向量化处理（即使文件路径发生变化）
- [ ] 数据库记录已处理文件的状态信息

#### 2.1.3 增量向量化处理
- [ ] 支持增量同步按钮，只处理新增或修改的文件
- [ ] 自动检测文件夹中新增的文件
- [ ] 自动检测文件夹中被修改的文件（基于内容MD5变化）
- [ ] 忽略未发生变化的文件（内容MD5未变化的文件）
- [ ] 支持文件路径变化但内容未变化的文件（无需重新向量化）

#### 2.1.4 文件状态跟踪
- [ ] 记录每个文件的处理状态（待处理、已处理、处理失败）
- [ ] 提供处理日志和错误信息记录
- [ ] 支持处理失败文件的重试机制

### 2.2 非功能需求

#### 2.2.1 性能要求
- [ ] 支持大型文件夹的快速扫描（万级文件）
- [ ] 向量化处理过程不影响系统其他功能
- [ ] 支持增量处理

#### 2.2.2 可靠性要求
- [ ] 处理过程中出现异常能够恢复
- [ ] 提供处理进度显示和状态反馈

#### 2.2.3 可扩展性要求
- [ ] 支持配置不同的文件类型过滤规则
- [ ] 支持插件化的内容解析器
- [ ] 支持不同的向量化模型
- [ ] 支持文件夹级别的配置管理

## 3. 技术设计

### 3.1 系统架构
```
┌─────────────────┐
│  用户界面层     │
├─────────────────┤
│  控制器层       │
├─────────────────┤
│  服务层         │
│ ├── 文件扫描器   │
│ ├── 状态管理器   │
│ ├── 增量处理器   │
│ └── 向量化服务   │
├─────────────────┤
│  数据访问层     │
│ ├── 文件元数据   │
│ └── 处理状态     │
├─────────────────┤
│  存储层         │
│ ├── 向量数据库   │
│ └── 关系数据库   │
└─────────────────┘
```

### 3.2 数据库设计

#### 3.2.1 文件跟踪表 (local_folder_files)
| 字段名 | 类型 | 描述 |
|--------|------|------|
| id | BIGINT | 主键 |
| folder_id | VARCHAR(32) | 知识库ID |
| file_path | TEXT | 文件完整路径 |
| file_name | VARCHAR(255) | 文件名 |
| file_size | BIGINT | 文件大小(字节) |
| last_modified | BIGINT | 最后修改时间戳 |
| md5_hash | VARCHAR(32) | 文件MD5哈希值 |
| status | ENUM | 处理状态(pending,processed,failed) |
| created_at | TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | 更新时间 |

### 3.3 核心组件

#### 3.3.1 文件扫描器 (LocalFolderScanner)
- 功能：递归扫描指定文件夹中的文件
- 输入：文件夹路径、支持的文件后缀列表
- 输出：文件信息列表（路径、大小、修改时间等）

#### 3.3.2 状态管理器 (FileStatusManager)
- 功能：管理文件处理状态
- 职责：记录文件状态、查询已处理文件、更新处理结果

#### 3.3.3 增量处理器 (IncrementalProcessor)
- 功能：识别需要处理的文件（新增或修改）
- 算法：对比当前文件与已处理文件的状态差异
- 核心机制：基于文件内容MD5哈希值判断文件是否需要重新向量化

#### 3.3.4 知识库管理器 (LocalKnowledgeBase)
- 功能：协调各组件完成知识库构建
- 职责：全量同步、增量同步、状态统计
- 重要原则：最大化复用现有流程、代码和环境
